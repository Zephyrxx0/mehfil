# Plan 01-02: Backwards Topological Timeline Scheduler & ICS Export

<objective>
**As a** celebration host or planner,  
**I want to** generate a backwards-scheduled milestone timeline from my celebration date with guest-scale adjustments, short-notice Immediate Action triage, and export it as an RFC 5545 `.ics` calendar file,  
**so that** our family has a crystal-clear vendor booking roadmap with 9:00 AM phone calendar reminders and zero short-notice panic.
</objective>

<action>
1. In `src/lib/engine/types.ts`, add timeline domain types:
   - `MilestoneBandId`: `'milestone_immediate' | 'milestone_t6m' | 'milestone_t3m' | 'milestone_t1m' | 'milestone_t2w' | 'milestone_day0'`
   - `TimelineTask`: `{ id: string; title: string; budgetCategory: BudgetCategory; leadDays: number; targetDate: string; isCompleted: boolean; isCriticalPath: boolean; dependencies?: string[]; notes?: string; }`
   - `MilestoneBand`: `{ id: MilestoneBandId; name: string; targetDate: string; isImmediateAction?: boolean; tasks: TimelineTask[]; }`
   - `TimelineSchedule`: `{ eventDate: string; milestoneBands: MilestoneBand[]; isCompressedMode: boolean; }`
2. In `src/lib/engine/timeline.ts`, implement:
   - `calculateBackwardsTimeline(eventDateStr: string, guestCount: number, todayStr?: string): TimelineSchedule`:
     - Computes UTC calendar day offsets backwards from `eventDateStr` (D-13):
       - T-6M (Venue & Date Lock): baseline 180 days before event.
       - T-3M (Catering & Vendors): baseline 90 days before event.
       - T-1M (Invites & Fittings): baseline 30 days before event.
       - T-2W (Final Numbers): baseline 14 days before event.
       - Day-Of (Execution & Celebrations): 0 days.
     - Applies guest scale multipliers:
       - If `guestCount > 250`: add 30 days to T-6M (210d) and T-3M (120d).
       - If `guestCount <= 80`: shorten T-6M to 120d (-60d) and T-3M to 60d (-30d).
     - Associates each task with its corresponding `budgetCategory` ID to support clickable category navigation (D-16).
     - Compressed Mode triage (ADR-0005, D-14):
       - If any calculated milestone date is before `todayStr` (or today's UTC date):
       - Flag `isCompressedMode = true`.
       - Extract all tasks whose calculated dates fall in the past and bundle them into an `milestone_immediate` ("Immediate Action (This Week)") band.
       - Sort triage tasks strictly by topological criticality:
         1. Venue & Stage Contract (Critical Path blocker)
         2. Catering Tasting & Menu Lock
         3. Photo & Film Booking
         4. Favors & Invites dispatch
       - Ensure non-blocking subsequent tasks remain in their normal future bands without intimidating red overdue alerts.
3. In `tests/engine/timeline.test.ts`, write unit tests:
   - Standard 6-month timeline: verify milestone dates are correctly calculated backwards from event date using pure UTC calendar math.
   - Large gathering (>250 guests): verify extended vendor lead times.
   - Short-notice event (e.g., date 45 days away): verify Compressed Mode triggers, overdue milestones are triaged into "Immediate Action (This Week)", and venue is sequenced first.
   - Category linking: verify all milestone tasks carry valid `budgetCategory` identifiers matching domain categories.
</action>

1. In `src/lib/engine/ics.ts`, implement:
   - `generateICS(schedule: TimelineSchedule, plan: Plan): string`:
     - Creates RFC 5545 compliant `VCALENDAR` format with `VERSION:2.0` and `PRODID:-//Mehfil//Celebration Planner//EN`.
     - Generates all-day `VEVENT` entries for each milestone band:
       - `DTSTART;VALUE=DATE:YYYYMMDD`
       - `DTEND;VALUE=DATE:YYYYMMDD` (start date + 1 day for all-day duration per RFC 5545).
       - Deterministic `UID` based on event title and milestone band ID.
       - `SUMMARY`: celebration title + milestone name (e.g. "Mehfil: Venue & Date Lock (T-6M)").
       - `DESCRIPTION`: includes milestone band name, target due date, linked budget category with formatted rupees (e.g. "Venue & Stage • ₹5,50,000"), and bulleted list of tasks to complete.
       - `BEGIN:VALARM`: sets display reminder alert at 9:00 AM (`TRIGGER:-PT15H` relative to midnight start, or explicit morning trigger per D-15).
   - `downloadICS(content: string, filename: string): void`:
     - Creates an in-memory `Blob([content], { type: 'text/calendar;charset=utf-8' })`.
     - Programmatically triggers browser download via temporary anchor element.
2. In `tests/engine/ics.test.ts`, write unit tests:
   - Validate RFC 5545 syntax: begins with `BEGIN:VCALENDAR` and ends with `END:VCALENDAR`.
   - Verify every milestone band produces a `BEGIN:VEVENT` with valid `DTSTART;VALUE=DATE` and `DTEND;VALUE=DATE`.
   - Verify presence of `BEGIN:VALARM` with action `DISPLAY` and valid trigger.
   - Verify event description contains linked budget category names and formatted rupee amounts.
</action>
