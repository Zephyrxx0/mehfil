3. Implement zero-sum idea displacement and exact inverse reversion in `src/lib/engine/budget.ts`:
   - Implement `export function adoptIdea(plan: Plan, idea: CuratedIdea): Plan`:
     - Create shallow copies of plan lines.
     - Locate target line matching `idea.category`. Throw error if category missing.
     - Identify flexible donor candidate lines: `line.lineType === 'flexible'`, `!line.isProtected`, and `line.category !== idea.category`.
     - Sort donor candidates in ascending order of `elasticityRank ?? 99` (Rank 1 Misc -> Rank 2 Entertainment -> Rank 3 Decor).
     - Sequentially drain capacity from each donor: calculate floor as `Math.round(line.baselinePaise * 0.40 / 100) * 100`. Compute available headroom as `Math.max(0, line.currentPaise - floor)`. Deduct up to `neededPaise` and record in `displacedDonors`.
     - Target category line receives full `idea.costPaise` (permissive model, D-04).
     - Create `IdeaDisplacementRecord` and append to `plan.adoptedIdeas`.
     - If donor capacity is exhausted (`neededPaise > 0`), clamp flexible lines to 40% floor, set `isInfeasible = true`, set `shortfallPaise = (existingShortfall || 0) + neededPaise`, and calculate deterministic remedies via `calculateShortfallRemedies`.
     - If feasible, verify sum invariant: `sum(lines.currentPaise) === plan.totalBudgetPaise`.
   - Implement `export function retractIdea(plan: Plan, ideaId: string): Plan`:
     - Locate `IdeaDisplacementRecord` in `plan.adoptedIdeas`. If missing, return original plan.
     - Target category line is debited by `record.costPaise`.
     - Reverse restore displaced paise: iterate `record.displacedDonors` in reverse order and add `displacedPaise` back to each donor line.
     - Filter out the idea record from `plan.adoptedIdeas`.
     - If the idea contributed to `shortfallPaise`, reduce `shortfallPaise` by `record.shortfallPaise`. If shortfall reaches 0, clear `isInfeasible` and `remedies`.
     - If still infeasible with remaining shortfall, recalculate remedies.

<threat_model>
## Threat Model Mitigation
- **T-05-01 (Arithmetic Float Leakage & Drift):** Idea costs or donor deductions introduce floating-point decimals into budget lines. *Mitigation:* All idea costs and donor displacements are strictly typed as integer `Paise`. Draining uses whole integer arithmetic and `Math.round(val / 100) * 100` for rupee alignment. Property tests check `Number.isInteger` on all lines.
- **T-05-02 (Protected Moment Inadvertent Erosion):** Scaling or idea adoption accidentally taps Protected Moment funds. *Mitigation:* Pure TS filter predicate explicitly enforces `!line.isProtected` on all donor selections and trim solvers; unit tests verify Protected line currentPaise never decreases during idea adoption or downward trimming.
- **T-05-03 (Lossy Reverse Reversion):** Retracting an idea restores incorrect amounts to donors, causing budget leakage. *Mitigation:* `IdeaDisplacementRecord` preserves exact `DisplacedDonor[]` snapshot with lineId and displacedPaise. Retraction restores exact recorded amounts in reverse order.
- **T-05-04 (Shortfall State Blocking Trap):** Organizers are trapped behind modal error dialogs when budgets exceed capacity. *Mitigation:* Permissive Shortfall State saves and operates non-blockingly (ADR-0002). Inputs remain responsive while 3 deterministic remedies offer immediate calculation paths.
</threat_model>
