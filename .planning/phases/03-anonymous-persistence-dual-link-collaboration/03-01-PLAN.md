# Plan 03-01: Database Schema, Supabase Infrastructure, Crypto Utilities & Local-First Persistence

<objective>
**As a** celebration organizer,  
**I want to** establish the PostgreSQL schema migrations for events, immutable plan versions, and change records under strict Row-Level Security, implement Web Crypto capability token generation and SHA-256 constant-time hashing, set up Next.js 15 Supabase client helpers with anonymous auth support, and construct a local-first persistence adapter with optimistic concurrency detection and a top-bar sync badge,  
**so that** any organizer can immediately persist their celebration plan anonymously without an account friction, compute secure capability hashes, and remain 100% resilient when working offline or before cloud credentials are provisioned.
</objective>

   - Table `public.plan_versions`: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`, `event_id UUID NOT NULL REFERENCES public.events(id) ON DELETE CASCADE`, `version_number INTEGER NOT NULL CHECK (version_number >= 1)`, `parent_version_id UUID REFERENCES public.plan_versions(id)`, `reason TEXT NOT NULL`, `lines JSONB NOT NULL`, `tasks JSONB NOT NULL DEFAULT '[]'::jsonb`, `totals JSONB NOT NULL DEFAULT '{}'::jsonb`, `is_accepted BOOLEAN NOT NULL DEFAULT true`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `CONSTRAINT uq_event_version UNIQUE (event_id, version_number)`.

   - Enable Row-Level Security on all 3 tables. Add RLS policies per `03-RESEARCH.md` §4.3:
     - `events_owner_all` FOR ALL USING `(auth.uid() = owner_id)` WITH CHECK `(auth.uid() = owner_id)`.

     - `plan_versions_owner_insert` FOR INSERT WITH CHECK `(EXISTS (SELECT 1 FROM public.events WHERE public.events.id = public.plan_versions.event_id AND public.events.owner_id = auth.uid()))`.
     - Strictly omit UPDATE and DELETE policies for `plan_versions` and `change_records` to enforce append-only immutability.
